【更新ログ】ログイン機能をDB認証に変更（2026-04-08）

■ 目的
- フロントの仮ログイン判定（固定メール/固定パスワード）をやめて、
  Render Postgres（Prisma経由）を参照した本物のログイン判定に切り替える。

■ 実施内容（コード変更）
1) 依存追加
- package.json
  - `bcryptjs` を追加
- package-lock.json
  - 依存解決結果を更新

2) ログインAPIを追加
- 追加: `app/api/login/route.ts`
- 仕様:
  - `POST /api/login` を受け取る
  - body から `email`, `password` を取得
  - `prisma.user.findUnique({ where: { email } })` でユーザー検索
  - `bcrypt.compare(password, user.passwordHash)` で照合
  - 成功: `200 { ok: true }`
  - 失敗: `401 { message: "ログイン情報が正しくありません。" }`
  - バリデーション不足: `400`
  - 例外: `500`

3) ログインフォームをAPI接続に変更
- 変更: `app/components/LoginForm.tsx`
- 変更点:
  - 固定判定（`test@example.com` / `test` など）を削除
  - `fetch("/api/login", { method: "POST" ... })` へ変更
  - 成功時に `/study` へ遷移
  - 送信中表示（`送信中...`）を追加
  - 失敗時メッセージ表示を維持

4) 既存画面導線（前回分の継続）
- `app/page.tsx` は `LoginForm` を表示
- `app/study/page.tsx` で `StudyInput` を表示

■ 動作確認の流れ
- `npm run dev` 起動
- ログイン実行
- 途中で `POST /api/login 401` が出たため原因を調査

■ 401の原因と対応
原因:
- Prisma Studio の `User.passwordHash` に平文 `test` が入っていた
- `bcrypt.compare` は「平文 vs ハッシュ」の比較前提なので失敗

対応:
- コマンドで `test` を bcrypt ハッシュ化
  - `node -e "const bcrypt=require('bcryptjs'); console.log(bcrypt.hashSync('test', 10));"`
- 出力された `$2b$...` 文字列を `passwordHash` に保存
- 再ログインで成功確認

■ 学びメモ
- `passwordHash` には平文を保存しない
- ログイン時は「入力パスワード（平文）」をハッシュ化済み文字列と比較する
- `npm run dev` と `npx prisma studio` は別ターミナルで同時起動できる
