gitの仕様　特にブランチ
コミットとpushの基本理解（前提）

コミット = 変更をローカルに保存する
push = GitHubなどのリモートリポジトリに送信する


ブランチとは何か
ブランチとは「作業の平行世界」。mainブランチから分岐して、自分だけの作業スペースを作る仕組み。
なぜブランチが必要か

mainに直接コードを書くと、バグがあれば即本番に影響する
ブランチがないと複数人が同時に別々の機能を作れない

ブランチの種類（例）

main … 本番コード。常に動く状態を保つ
feature/○○ … 新機能を安全に作る作業場所。mainには影響しない
bugfix/○○ … 別の人が同時並行で作業できる。mainを壊さない


基本的な操作の流れ
bashgit branch feature/new-login    # ブランチを作る
git checkout feature/new-login  # そのブランチに移動
# ← ここでコミットしてもmainには影響ゼロ

git checkout main
git merge feature/new-login     # 完成したらmainに合流（マージ）

まとめ
ブランチとは「mainを壊さずに実験できる安全地帯」。作業が終わったらmergeでmainに合流し、必要に応じてコードレビューもここで行う。
